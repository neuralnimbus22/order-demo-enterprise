RCA Orchestrator (two-paths) — the hero

Symptom

"did an order make it through?"
▼ on failure → diagnose

Stage 1 — Shared infrastructure
both paths depend on these
kafka redis db
Stage 2 · Order path
auth → order + product-catalog (only if sku)
Stage 2 · Payment path
payment
Stage 3 — Convergence
inventory
When auth goes down, the whole order-path group turns red while payment-path stays green — you see which side broke at a glance, instead of reading 13 results.
Other orchestration patterns exist too (run-everything sequential audit, and a single-step signature diagnoser) — this topology-grouped version is the most legible for triage.
user-session is intentionally absent from the diagnose stages — it sits off the order pipeline (UI login only) and is never on the "order not fulfilled" symptom path.
One symptom — "order not fulfilled" — seven distinguishable root causes. That's the discrimination this system is built to demonstrate.
